## 1. 원칙

- 담당자 배정: A 이지은 · B 주정현 · C 박소빈 · D 박선우 · E 노현섭.
- 목업의 화면 분류 A~E와 이 안내의 업무 묶음 A~E는 서로 다릅니다.
- P0 핵심 → P1 보완 → P2 후순위는 제안 순서입니다. 공개 전 최소 차단·신고를 완료합니다.
- 현재 버튼은 업무 안내만 엽니다. 기존 화면·기기·테마·선택 상태는 닫을 때 그대로 유지됩니다.

| 인증과 소속 | A 로그인 → E 동네 인증 | A는 누구인지 식별하고 E는 어느 동네에서 이용 가능한지 판정합니다. 각 API 담당이 권한 검사를 적용합니다. |
| 물건과 기간 | B 가능 기간 → C 승인 점유 | 검색·달력은 C의 같은 날짜 규칙을 사용합니다. 승인 시 C가 다시 검사하며 B의 기간 수정과 동시에 충돌하지 않게 설계합니다. |
| 채팅과 약속 | C 처리 규칙 → D 화면 연결 | C는 약속 모델·API·상태·시간 검증을 소유합니다. D는 채팅 속 입력 UI·카드·수락 버튼과 메시지를 구현합니다. |
| 프로필 | A 화면 ← B 물건 / C 지표 / E 신고·차단 | 프로필 화면에서 다른 도메인의 데이터를 조립하되, 수정 규칙은 원래 도메인에 유지합니다. |
| 제재 | E 결정 → A 적용 → C 기존 거래 | 운영 조치는 E가 결정하고 A가 계정에 반영합니다. 미반납 거래 처리는 C와 합의하고 결과 알림은 D가 전달합니다. |
| 알림 | C·E 사건 → D 전달 | 거래·신고 처리 커밋 이후에 알림을 생성하고 중복·누락·재처리 계약을 정합니다. |
| 공통 업무 | 별도 주 담당 지정 + 전원 참여 | 공통 UI·통합·관측 기반은 특정 도메인에 자동 배정하지 않습니다. 각 도메인은 자신의 화면·테스트·문서·성능 결과를 책임집니다. |

## 5. 의사결정

### 결정: 동네 모델

- 배경: 기획안는 학교·회사·아파트, 목업 가입은 동네/단지 중심
- 결정: 초기 범위는 준비된 생활권 커뮤니티로 제한한다. 학교·회사 소속 증명은 위치 인증과 별도로 본다.
- 담당: 노현섭

### 결정: 위치 인증의 의미

- 배경: 목업은 현 위치로 ‘사는 이웃’을 확인한다고 설명
- 결정: 위치 확인은 해당 반경 내 존재 확인으로 표현한다. 실제 거주·재직·재학 증명이라고 표시하지 않는다.
- 담당: 노현섭

### 결정: 거리 기준

- 배경: 개인 좌표를 이후 사용하지 않는다는 문구와 가까운 순·거리 표시가 공존
- 결정: 기본은 동네 중심→공용 장소 거리로 하고 문구를 명시한다. 내 위치 기준을 쓰려면 별도 동의·일시 사용 흐름을 정의한다.
- 담당: 노현섭·주정현

### 결정: 기간 경계

- 배경: 시작일·반납일 모두 포함
- 결정: 기존 종료일과 신규 시작일이 같아도 겹침이다. 승인 검사는 기존 시작≤신규 종료 AND 신규 시작≤기존 종료 기준으로 통일한다.
- 담당: 박소빈

### 결정: 겹치는 대기 요청

- 배경: 목업은 동일 물건의 대기 요청을 여러 개 표시
- 결정: 대기 요청의 겹침은 허용하고 승인된 점유의 겹침은 금지한다. 승인 실패한 나머지 요청을 자동 거절할지는 별도 정책으로 정한다.
- 담당: 박소빈

### 결정: 연체와 후속 대여

- 배경: 연체 물건과 날짜 검색이 함께 존재
- 결정: 실제 미반납 중 새 전달을 허용하지 않는다. 후속 요청·승인 제한 범위와 이미 승인된 다음 거래의 대응을 정한다.
- 담당: 박소빈

### 결정: 차단 중 진행 거래

- 배경: 차단 시 대화·물건 비노출이지만 대여는 유지되어야 함
- 결정: 신규 관계는 막고 기존 거래 기록·반납 처리·운영 문의 경로를 유지한다. 기존 거래에 한한 채팅 허용 여부를 화면 문구와 함께 확정한다.
- 담당: 노현섭·박소빈·박선우

### 결정: 약속과 날짜 변경

- 배경: 약속 시트는 전달/반납 날짜가 고정
- 결정: 약속은 시간·공용 장소만 바꾼다. 대여 기간 변경은 별도 기능이며 암묵적으로 제공하지 않는다.
- 담당: 박소빈

### 결정: 반납 약속 준수

- 배경: 목업에는 준수 분수와 실제 거래 기반 설명
- 결정: 확정된 반납 시각을 기준으로 집계하는 안을 우선 검토한다. 소유자의 늦은 확인, 약속 없는 거래, 수정된 약속 처리 규칙을 먼저 확정한다.
- 담당: 박소빈

### 결정: 카테고리 불일치

- 배경: 등록은 5종, 공통 검색/관리자는 더 많은 분류
- 결정: 하나의 기준 목록을 정해 등록·필터·차트 모두 공유한다.
- 담당: 주정현

### 결정: 신고 대상

- 배경: ‘이 물건 신고하기’가 이름 기반 신고 모달로 연결됨
- 결정: 회원·물건·대화 중 무엇을 신고했는지 별도 대상 유형과 ID로 보존한다.
- 담당: 노현섭

### 결정: 관리자 진입

- 배경: 로그인 화면에 관리자 콘솔 데모 버튼 존재
- 결정: 실서비스에서는 서버의 관리자 권한 검사를 필수로 한다. 데모 바로가기는 제거하거나 권한 있는 사용자에게만 보여 준다.
- 담당: 이지은·노현섭

### 결정: 운영 통계

- 배경: 목업 값은 예시이며 카테고리 합계와 등록 총수가 다를 수 있음
- 결정: 예시 숫자를 구현 검증 기준으로 쓰지 않는다. 동일 데이터·기간으로 집계하고 합계/비율을 검증한다.
- 담당: 노현섭
