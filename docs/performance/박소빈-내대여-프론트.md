# 박소빈-내 대여 프론트 최초 로딩 개선

> 양식: [성능 측정 양식](성능%20측정%20양식.md). 화면의 조회·렌더링 비교에 맞춰 브라우저 계측 사용. k6·실제 서버·SQL 측정과 별도 구분.

## 1. 문제

- 진입 시 빌린·빌려준 전체 페이지 조회 후 모든 거래 상세를 6개씩 조회하는 구조.
- 화면에 필요하지 않은 반대 탭·다음 페이지의 상세까지 첫 카드 표시를 지연하는 문제.

## 3. 변경

- 현재 탭·필터에 필요한 20건만 조회 후 기본 카드 즉시 표시.
- 표시할 거래만 6개 단위로 상세 조회. 상세 준비 전 행동 버튼 비활성·로딩 표시 유지.
- 전체 탭·필터 건수는 기존 C_030 `/rentals/summary`로 조회. ACTIVE·연체 중복 합산 방지.
- 기존 C_029의 role·status·overdueOnly·page·size 사용. API 계약·DB·인증 변경 없음.
- `완료·거절`의 RETURNED·REJECTED·CANCELED·EXPIRED 스트림을 생성 시각 DESC·숫자 ID DESC로 병합. 스트림별 버퍼·다음 페이지 보존.
- 나머지 거래는 기존 Button의 `더 보기`로 추가. 다음 페이지 실패 시 기존 목록·커서 유지.
- 알림 대상은 상세로 역할 판정 후 해당 탭에 고정. 첫 페이지 밖 거래 포함·중복 제거·포커스 이동 유지.
- 상태 변경·409 재조회·상세 재시도 후 전체 건수 갱신.

### 기능 검증

- 단위 테스트: 1,000건 첫 20건 요청, 다음 페이지 누락·중복 방지, 완료 4상태 편중 병합, 연체 분리, 실패 시 커서 보존, 큰 숫자 ID·마이크로초 정렬, 전체 건수 검증.
- 브라우저: 20→40건 추가 조회, 다음 페이지 실패 시 기존 20건 유지 및 재시도 후 40건 중복 없음.
- 브라우저: 상세 실패 시 버튼 차단·재시도 복구, 확정 약속·사유·채팅방 연결 유지.
- 브라우저: 409 후 재조회 실패 시 버튼 차단, 재시도 뒤 최신 버전 취소 성공·전체 건수 갱신.
- 브라우저: 목록 밖 `rentalId=10999`의 OWNER 탭 선택·21개 카드 중복 없음·포커스 이동·대상 상세 1회.
- 브라우저: 빠른 탭/완료 필터 전환 뒤 현재 역할·완료 상태만 표시.
- 브라우저: 요약 실패 시 전체 건수는 `–`·목록 20건 유지, 재시도 후 전체 건수 복구.
- 브라우저: 알림 대상 조회 실패 후 재시도로 올바른 탭·21개 카드·포커스 복구.
- 스타일 실측: 카드 간격 16px·패딩 20px, 날짜/약속 정보 박스 패딩 12px 16px·글꼴 14px. 기존 프로토타입·컴포넌트 값 유지. UI 확장은 `더 보기`와 상세 준비 중 로딩 표시.
- [검증 화면](raw/rental-frontend-check.png): 합성 거래 1,000건의 전체 탭 건수 500씩·첫 페이지 표시.

## 5. 한계

- 실제 서버·MySQL·운영망 미측정. SQL 횟수·잠금·서버 p95 수치 없음.
- 개발 모드에서 모듈 워밍업 후 비교. 프로덕션 번들·로그인·헤더·LCP·모바일 기기 성능으로 일반화 불가.
- 100ms 타이머는 통제한 입력 조건. 실제 API 비용과 브라우저 타이머 편차는 별도.
- 최초 화면의 완료 기준이 변경 전 전체·변경 후 첫 페이지로 다름. 첫 카드 DOM·초기 요청 수를 주 지표로 사용.
- 일반 `전체` 진입 측정. 완료 필터는 최대 4개 상태 스트림 조회, 비연체 ACTIVE 필터는 연체를 건너뛰며 추가 페이지 조회 가능. 일반 진입과 같은 요청 상한 보장 없음.
- 오프셋 페이지네이션 도중 서버 데이터 변경 시 경계 변동 가능. 클라이언트에서 이미 표시한 ID 중복 제거. 커서 기반 API 도입은 별도 계약 변경 대상.
