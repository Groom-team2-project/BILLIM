# 박소빈-약속 전체 조회 일괄 조회 개선

## 1. 문제

- 전달·반납 약속 전체 조회 시 슬롯마다 확정·대기 제안 조회 반복.
- 제안 응답마다 공용 장소 조회 반복. 같은 장소를 공유해도 조건 조회 SQL 반복.
- 이전 [변경 응답 단일 슬롯 개선](박소빈-약속응답-단일슬롯.md)은 쓰기 응답 대상이며 전체 약속 GET의 반복 조회는 유지된 상태.

## 3. 변경

- 확정 제안 ID를 모아 `findAllById`로 한 번 조회.
- 전달·반납 슬롯의 PROPOSED 제안을 슬롯 ID 목록으로 한 번 조회 후 슬롯별 분류.
- 응답에 필요한 장소 ID를 중복 제거하고 **대여의 동네 ID 조건을 포함해** 한 번 조회.
- 빈 확정·장소 ID 목록은 해당 SQL 생략. 슬롯이 없으면 기존과 같이 즉시 빈 응답.
- 슬롯 목록의 기존 순서를 유지하고 제안·장소 Map은 해당 요청 안에서만 사용.
- 단일 슬롯과 전체 조회의 응답 조립·정합성 검사·허용 행동 공유. 단일 슬롯의 기존 개별 조회 방식 유지.
- 장소 이름은 제안 당시 스냅샷 유지. 비활성 장소도 메타데이터 반환, 다른 동네 장소는 좌표·안내를 반환하지 않는 기존 동작 유지.
- API·DTO·DB 구조·인덱스·인증 정책·잠금·트랜잭션 경계 변경 없음.

## 4. 결과

### 전후 SQL·서비스 시간

SQL은 모든 180개 표본에서 해당 상태의 같은 값 관측. 시간은 회차별 p50/p95의 3회 중위값이며 전체 표본을 합친 p95와 구분. 단위 ms.

| 상태 | SQL 전→후 | p50 전→후 | p95 전→후 |
| --- | ---: | ---: | ---: |
| 슬롯 없음 | 3 → 3 | 2.642 → 3.037 | 4.216 → 4.875 |
| 두 슬롯·제안 없음 | 5 → 4 | 2.974 → 3.608 | 5.297 → 4.979 |
| 두 슬롯·대기 제안만 | 7 → 5 | 3.018 → 3.170 | 6.743 → 4.271 |
| 두 슬롯·확정 제안만 | 9 → 6 | 3.623 → 3.251 | 6.275 → 4.570 |
| 확정+대기·장소 1개 공유 | 11 → 6 | 3.699 → 2.890 | 5.154 → 5.495 |
| 확정+대기·장소 2개 사용 | 11 → 6 | 3.563 → 2.752 | 4.080 → 3.182 |

- 확정+대기 제안이 있는 두 슬롯은 SQL **11→6회, 45.5% 감소**. 대기만 28.6%, 확정만 33.3%, 제안 없음 20% 감소.
- SQL 6회 구성: 활성 회원 1 + 대여 1 + 슬롯 1 + 확정 제안 1 + 대기 제안 1 + 장소 1.
- 모든 측정 호출 성공·응답 일치. 동일 장소 공유 여부에 따른 반복 장소 조회 제거.
- p95는 대기·확정·서로 다른 장소 조건에서 감소했지만, 장소 공유 조건과 SQL 변화가 없는 슬롯 없음 조건에서는 증가. 머신·JVM·짧은 표본의 변동 포함.
- 따라서 **SQL 감소를 개선의 주 근거로 사용**. 전체 조건의 안정적인 응답 시간 개선·최대 처리량 개선으로 해석하지 않음.

### 회귀 검증

- 계측 후 상태별 SQL 상한 3/4/5/6회 추가. 기준 코드에 현재 테스트를 적용하면 SQL 상한 실패 예상.
- 다른 슬롯이 빈 경우, 과거 SUPERSEDED 제안 100개, 슬롯이 참조하지 않는 확정 제안의 응답 제외 확인.
- 비활성 장소의 좌표·안내·스냅샷 유지, 다른 동네 장소의 좌표·안내 제외 확인.
- APPROVED·ACTIVE·RETURNED × 양 당사자의 전체 응답·허용 행동을 단일 슬롯 응답과 비교.
- 없는 확정 참조·다른 슬롯 확정 참조·확정 상태 불일치·중복 대기 제안 거부 검사 유지.
- 관련 약속·대여 흐름 테스트 55건 통과. 기존 단일 슬롯 명령의 SQL 상한·멱등 재전송·동시성·롤백 검사 포함.
- `backend/./gradlew build` 통과. 전체 테스트 983건, 실패·오류·건너뜀 0.

## 5. 한계

- 소규모 합성 데이터·단일 요청자의 서비스 호출 기준. 실제 HTTP p95·프론트 체감 지연·동시 사용자 부하 미측정.
- 시간 표본은 회차당 60개로 작고, 독립 JVM 실행의 JIT·GC·호스트 자원 상태 차이 포함. 워밍업 후에도 실행 순서 효과를 완전히 제거하지 못한 한계.
- 전후 같은 서버·DB를 교차 실행한 장시간 비교는 아님. 시간 개선 비율 일반화 제외.
- 세션 인증 조회 비용은 포함하지 않으므로 이전 HTTP·k6 측정의 SQL 수와 직접 비교 제외.
- 과거 이력 100개는 기능 회귀 조건이며 위 시간 표본의 데이터 규모와 구분.
- 계측 원본은 SQL 상한 및 추가 경계 테스트 작성 전의 동일 측정 테스트로 수집. 최종 테스트 소스 지문과 다를 수 있으며 프로덕션 소스 지문은 원본에 보관.
- 잠금 보유 구간 변경·캐시·인덱스 도입·명령 HTTP 부하 측정은 이번 범위에서 제외.
