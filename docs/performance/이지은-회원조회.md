## 2. 요청당 쿼리

응답시간과 달리 환경에 무관하게 재현되는 값. SQL 로그에서 요청 스레드만 집계.

| API | 쿼리 수 |
| --- | --- |
| 내 프로필 | 5건 |
| 이웃 프로필 | **9건 → 8건** (회원 조회 병합 후) |

**이웃 프로필 8건 구성**

| 쿼리 | 용도 |
| --- | --- |
| auth_sessions + members (조인) | 세션 복원 |
| members | 조회자·대상 함께 조회 |
| community_memberships · communities | 대상 소속·동네 이름 |
| rentals | 거래 당사자 판정 |
| community_memberships | 조회자 활성 동네 |
| blocks ×2 | 양방향 차단 · 단방향 차단 |

## 3. 확인한 두 가지

**회원 조회 병합** — 조회자와 대상을 각각 읽어 회원 테이블을 두 번 왕복. `findAllById`로 묶어 **9건 → 8건**.

**세션 유휴 시각 갱신 주기** — 모든 인증 요청이 세션 행을 읽는데, 유휴 판정용 `last_seen_at`을 매번 쓰면 같은 행에 쓰기가 몰림. 현재 설정은 5분 주기로 묶어 쓰기를 건너뜀(`session-touch-interval`).

| 설정 | 요청당 세션 UPDATE |
| --- | --- |
| 0s | 1건 (매 요청) |
| **5m (현재)** | **없음** (주기 경과 시에만) |

대가는 유휴 만료 판정이 최대 5분 늦어지는 것.

## 4. 동시 수정 — 쓰기 경합

이름 수정의 충돌 방어는 두 겹. `expectedVersion` 선검사로 오래된 화면의 수정을 거르고, 엔티티 `@Version`으로 커밋 시점의 충돌을 차단. 같은 버전으로 20건 동시 전송 후 어느 경로를 타는지 확인.

| 응답 | 건수 |
| --- | --- |
| 200 성공 | 1 |
| 409 — `currentVersion` 포함 (선검사 경로) | 10 |
| 409 — **`currentVersion` 없음** (`@Version` 경로) | **9** |

정합성 정상 — 성공 1건. 단, 실패 19건 중 9건의 응답 모양이 다름. 두 트랜잭션이 같은 버전을 읽어 선검사를 함께 통과하면 커밋에서 밀린 쪽은 `OptimisticLockingFailureException` 경로로 빠지고, 이 경로는 `currentVersion` 미포함.

**조치** — 프론트의 분기 조건이 `currentVersion` 존재 여부였던 탓에 그 9건은 "다시 불러오기"가 아닌 일반 오류 토스트. 두 경로가 공유하는 `code === "VERSION_CONFLICT"`로 판정 변경.

**후속** — 서버 응답 통일에는 밀린 쪽의 현재 버전 재조회가 필요하고, 실패한 트랜잭션에서는 불가해 별도 트랜잭션 요구. 클라이언트가 해당 필드에 더는 의존하지 않으므로 보류.

## 5. 한계

- **응답시간·처리량은 근거로 쓸 수 없음.** 같은 설정·같은 코드로 측정한 처리량이 817.6 / 536.2 / 415.7 req/s로 **2배 편차.** 부하 생성기와 서버가 같은 머신이고 측정 사이에 빌드·테스트가 돌았음. 워밍업·반복 측정도 없음
- 그래서 위 두 변경의 **응답시간 효과는 미검증.** 쿼리 수·UPDATE 발생 여부만 확정
- 다음 측정에서 고칠 것 — 백그라운드 정지, 워밍업 후 3회 반복, 중위값·편차 기록. 가능하면 부하 생성기 분리
- 운영은 낮은 사양에 원격 DB(RDS) — 쿼리 1건의 비용이 로컬보다 큼. 효과 판단은 운영 측정에서
- 시드가 전부 `RETURNED` — 요청 자동 만료 작업이 행을 잠그는 상황은 재현되지 않음

## 6. 재현

```bash
# 데이터 적재
docker exec -i billim-mysql-1 mysql -ubillim -p"$MYSQL_PASSWORD" billim \
  --default-character-set=utf8mb4 < docs/performance/scripts/seed-load.sql

# 테스트 세션 — 토큰 원문을 쿠키로, SHA-256을 auth_sessions.token_hash로 (로컬 전용)
# 부하
k6 run -e SESSION=<토큰> -e TARGET=4 docs/performance/scripts/member-read.js

# 동시 수정 — CSRF는 서버에서 받은 값을 쓴다(마스킹되어 DB 값과 다름)
CSRF=$(curl -s -H "X-Requested-With: XMLHttpRequest" -H "Cookie: BILLIM_SESSION=<토큰>" \
  localhost:8080/api/v1/auth/csrf | jq -r .csrfToken)
k6 run -e SESSION=<토큰> -e CSRF="$CSRF" -e VERSION=<현재 version> \
  docs/performance/scripts/member-rename-race.js

# 요청당 쿼리 수 — 요청 스레드의 SQL 로그만 집계
grep -c "nio-8080-exec.*org.hibernate.SQL" <로그>
```
