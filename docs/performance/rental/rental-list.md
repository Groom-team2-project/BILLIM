## 재현

저장소 루트에서 실행.

```bash
cd backend
./gradlew bootJar
cd ..
docker compose -f performance/rental/compose.yaml up -d --build --wait
python3 performance/rental/run.py
```

- 카카오 키·실제 로그인 불필요. 기존 개발 DB와 분리.
- 최초 전용 DB는 자동 생성, 기존 데이터가 있으면 조건 검증 후 재사용.
- 대기 요청 만료 시 실행 중단. 동일 상태로 비교하려면 별도 새 전용 DB 필요.
- 종료: `docker compose -f performance/rental/compose.yaml stop`. 데이터 볼륨 보존.

## 한계

- 한 PC에서 서버·DB·부하 도구 실행. 다른 개발 서비스와 Docker 자원 공유, 운영 성능으로 일반화 불가.
- 1초 대기 포함 9.52req/s는 시나리오 요청률. 서버 최대 처리량 아님.
- 첫 페이지·한 계정·합성 데이터만 측정. 사진과 승인·진행·반납 상태의 비용 제외.
- CPU·메모리 시계열과 요청별 SQL 수 미수집. 별도 시점 자원 스냅샷은 부하 시점 증거로 사용하지 않음.
- EXPLAIN은 실제 ORM과 같은 필터·정렬의 SELECT * 조회로 별도 확인. 계획만으로 응답 지연의 지배적 원인 단정 불가.
- 2026-10-24 확인 시 대기 요청이 만료되어 EXPIRED 500·REJECTED 250·CANCELED 250건. 측정 당시 분포와 구분 필요.
- 다음 단계: 요청별 SQL 수 수집 → 데이터 증가·페이지 이동 비교 → 병목 확인 → 개선 승인 및 재측정.
- 대여 생성·겹치는 요청 동시 승인·멱등 재전송·약속 동시 변경은 별도 후속 시나리오.
